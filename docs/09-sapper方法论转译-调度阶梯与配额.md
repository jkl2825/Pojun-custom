# 09 · sapper 方法论转译：把冠军的调度纪律装进 Pojun

> 来源：sapper-v2（腾讯云智能攻防挑战赛线上赛冠军）的 doctrine 与运行机制。
> 目的：只取**可迁移的方法论**，不搬它的竞赛形态（多 agent 军团 + tmux TUI）。
> 前提判断：Pojun 已有事实-意图双图、独立 worker 会话、分层摘要、角色模型绑定和事件驱动闭环，应复用这些基础能力，把资源决策、协作与经验继承接成闭环，不另起一套 CLI 框架。

## 2026-11-05 · 本轮落地状态

以下旧方案中的动态四档预算、自动模型升档和新 task_state 表仍是建议，不是本轮已实现功能。当前代码边界：
- 自主 planner 每轮最多成功创建 4 条；普通待领队列上限 `max(4, 2 * 实际运行 worker 数)`。计数、去重、节点/锚点/血缘写入同一事务，取消的规划轮不能迟到提交。人工直投不受自主队列背压，但仍保留校验和审计。
- 15 分钟无产出先纠偏；25 分钟且已纠偏后请求 planner 比较价值、评估不同角度；45 分钟持续无产出停放。L2 事件不自动编造任务，不盲目增加并发。
- `collaborates_with` 为独立会话的不同角度短单：只允许已到 L2、priority≥8 的本图运行中原始意图；须有明确差异、假设、成功判据和本图有效证据，资产是原方向锚点的非空子集。接续链/协作子单不能递归派协作。
- 每源最多一次（源永久标记，删除子单不返还），每任务最多一个待领/运行/暂停中的协作；使用现有 worker 名额。遗留队列即使超上限也保留一个协作位，协作优先被下一空闲 worker 领取，普通队列不继续扩张。历史待领意图不删除或重排。
- 协作累计最多 600 秒，使用 `collaboration_wall_ms` 记录每次执行尝试（含暂停和 provider 重试）；入口重读余额，非法/耗尽时不调用 LLM，硬上下文截止约束单次模型请求，父暂停/终止不伪装成预算超时。进程硬崩溃前尚未写回的耗时不等价于持久租约预扣。
- `parent_ids / briefing_ids / continues / collaborates_with` 驱动系统生成交接卡：最多 6 条事实/发现、3 个相关意图、总长 2400 rune，包含置信度、证据摘要/存在标记、停止原因和已有产出。关联任务仅只读摘要，运行拓扑和原始证据不跨图转发；全部自由文本隔离为不可信数据。
- `dispatch_budget` 显示实际 worker 数、普通/总队列、当轮额度、协作占用、剩余轮数和已配置截止时间的余额。没有配置总时限的任务不伪造剩余分钟；模型绑定/故障转移不改，没有自动选贵模型或新增付费配置。

本轮验证与上线结果以原 `DEPLOY-本地部署说明.md` 的最新记录为准。代码通过不等于已证明单位 Token 的有效产出提升，仍需后续授权运行对照。

## 一、先说清楚：两套形态的本质差异

| | sapper | Pojun |
|---|---|---|
| 单元 | 多道题并行，每道题一个或多个 agent 窗格 | 一个任务一个目标图，多意图并行 |
| 调度者 | 一个 LLM 指挥官读 board 决策 | planner 每轮新会话 + 引擎事件驱动 |
| 执行者 | 外部 CLI agent（tmux 窗格） | 内置 worker（工具直调） |
| 失败处理 | 换人 / 换脑 / 停放 | `steer_work` 纠偏 / `kill_work` 止损 |
| 状态载体 | 每题目录下的 JSON 图 + 屏幕文本 | Postgres 双图 + activity 流水 |

**结论：不搬 tmux 形态，但保留独立视角协作。** 外部 CLI 是 sapper 的实现选择，不是其协作价值的全部原因。Pojun 的 worker 也有独立上下文和共享图，可用显式的不同角度意图表达同题协作；要区分“重复干同一件事”与“在同一范围验证不同假设”。队列积压要求比较机会成本和限制名额，不足以否定所有协作。

真正要学习的是全局资源决策、经验证知识的复用、交接与收官构成的闭环，而不只是超时阈值。

## 二、六条可迁移方法论

### 1. 单一看板 + 固定节拍重读

**原理**：决策者必须每轮取一次新鲜快照，禁止复用上一轮结论。sapper 的 board 是一张 100 行内的表（平台状态 + 每题图统计 + 窗格列表 + `budget_left` + `generals` 计数），指挥官每 60 秒重读一次。

**Pojun 现状**：`renderGraphOverview` 已经把态势拼进 planner 每轮的 user 输入（`agent/planner.go:287`），触发事件拼在最前（`:173`）——**这条已经有了，而且实现更干净**（结构化查询 vs 屏幕抓取）。

**缺口**：看板里没有"预算水位"和"贵资源用量"。planner 不知道还剩多少轮、也不知道自己已经用掉多少高档模型调用。

**动作**：`graph_overview` 增加一行 `run_stats: rounds_left=… smart_used=… parked=…`。

### 2. 每轮有限动作数（爆炸半径控制）

**原理**：sapper 明文规定"每轮至多两个决定性动作"。理由不是省 token，是**便于归因**：一轮做一件事，出问题能定位；一轮做五件事，只能看到总结果变好或变坏。

**Pojun 现状**：planner 单轮最多派 4 个意图（`agent/planner.go:298`），已有上限但未区分"决定性动作"与"常规派单"。

**动作**：把"升级类动作"（换模型、加第二角度、park）单独限流为**每轮至多 1 个**，与普通 `add_intent` 分开计数。理由：升级是昂贵且不可逆的，连做两个会让归因失效。

### 3. 硬阈值阶梯：把"卡住"从单值变成四档（核心）

**原理**：sapper 的 4.6 表把"卡住"拆成四档，每档绑定一个动作与成本，且声明为 single source of truth——任何其他章节不得覆盖、不得跳级。它的价值不在具体分钟数，而在**把模糊判断变成可执行规则**：模型不需要"感觉"该不该升级，只要查表。

**关键：阈值不能照抄。** sapper 的 23 分钟/题来自"24 slot-hours ÷ 63 题"。Pojun 的等价公式应该是：

```
单意图预算 T = 剩余总预算 / max(1, 未完成意图数)
L1 = 0.4T   # 战术纠偏（steer_work）
L2 = 0.7T   # 换角度（同资产第二条意图）
L3 = 1.0T   # 升档模型
L4 = 1.3T   # 停放（blocked + 原因）
```

这样换场景、换预算自动适配，不会像 sapper 那样换比赛就全部失配。

**Pojun 现状**：`idlestop` 是"连续 3 轮无写回 + 至少 3 分钟 → 收场"（`agent/idlestop.go:83,90`），是**单值**且动作只有"结束"；heartbeat 巡查能 `steer_work`/`kill_work`（`server/engine.go` 心跳分支），但**判据里没有"这个意图已经跑了多久"这个维度**。

**缺口**：没有时间轴，所以"跑 40 分钟仍在推进"和"跑 40 分钟毫无进展"被同等对待；而 sapper 战报里 84 分钟静默后引爆 12 面旗的案例说明，**静默 ≠ 失败**，过早收场是最大浪费。

**动作**：见第三节的阶梯设计。

### 4. 三通道情报栈

**原理**：sapper 的情报有三条通道，可靠性递减、时延递增：
1. **持久广播**（`hint` 写成图上的 hint fact）——重启后仍在，给未来所有 worker 读；
2. **同单元共享**（多 pane 共享同一个 `.sapper`）——零成本，靠 mission 提醒"先读图"；
3. **入场预置**（spawn 时把已知打法写进 mission）——最便宜也最有效，只对该 worker 生效。

**Pojun 现状**：`hint` 节点类型存在（`db/constants.go:10`），跨任务只读继承存在（`agent/tools.go:872`）；缺的是"**确认的手法**"这一层抽象——现在 finding 是漏洞结论，不是可复用的打法。

**动作**：给 finding 增加 `technique` 结构化字段（手法名 + 适用指纹 + payload 摘要），planner 派意图时按目标指纹召回同族手法，写进意图描述。这比"多一层 hint"更接近 sapper 的同族迁移，但**不假设目标同构**——只做"相似指纹召回"，命中率低时自然退化为普通派单。

### 5. 贵资源配额账本 + 闲置审计

**原理**：sapper 把 smart 模型的用途**穷举锁死**（`SKILL.md:192-194` 明写 four jobs），并规定"易题队列非空 → 永不派将军"；预算过半时审计"将军用量 < 攻题数 × 20%"就判定囤积，立即补派。

**注意**：sapper 自己在这条上就翻车了——`worker.sh:41` 的默认模型是 `${SAPPER_MODEL_DS:-${SAPPER_MODEL:-glm-5.3[1m]}}`，未设 `SAPPER_MODEL_DS` 时裸 spawn 直接落到最贵档，正面违反它自己写的"默认全部 flash"。**教训：配额纪律必须由代码强制，不能只写在提示词里。**

**Pojun 现状**：已有角色模型绑定、任务配置链、用途专属配置和 provider 故障转移（`server/task_llm.go`），并非只能单模型；欠缺的是按意图价值/难度升降档的预算账本与准入。本轮保留既有配置，不擅自挑选或激活昂贵模型。

**动作**：先做两档（`fast` / `smart`），并在**选择模型的函数里**做断言：非白名单场景请求 smart → 拒绝并降级，日志记一条 `tier_denied`。这样纪律不依赖提示词。

### 6. 收官对账：捕获 ≠ 交付

**原理**：sapper 在最后一段停止开新局，专做三件事：确认每面已捕获的 flag 都已提交、关闭平台实例、写总结。

**要修正的认知**：战报声称这步"挖出 4 分"，但事件日志显示 18:57:34 后零计分——那 4.14 分来自之前的正常解题。**对账的价值不是翻盘，是防漏**：已捕获未提交、有结论无证据、有证据无结论，这三类在收尾时必须清零或显式标注。

**Pojun 现状**：`auto_finish` 只按轮数/覆盖率/空转收尾（`server/auto_finish.go:98-108`），不做清点。我们自己有 28 个无流量证据的 finding，就是活证据。

**动作**：settle 前插 `reconcile`，输出一份可交付的对账簿。

### 7. 交接文档：对抗上下文死亡

**原理**：sapper 的指挥官会被压缩、被杀、被替换，所以它维护一份 <150 行的 STATE（分配表 / 停放表 / 情报日志 / 队列 / 下一步），双触发重写：外部信号（context-low 提示）或内部计数（ITERATIONS 达 8）。

**Pojun 现状**：`agent/compaction.go` 有压缩预算与死锁保护，但压缩产物是"对话摘要"，不是**结构化交接**。

**动作**：不学它写 md。落一张 `task_state` 表（当前分配、停放清单、已确认手法、下一步），压缩后由引擎重新注入。**结构化 > 文本**，且可被 UI 直接渲染。

### 8. 守护层分层（含一个反例）

**原理**：保活与决策分离——watchdog 只负责"进程还活着"，不做选题派活。

**反例**：sapper 的 watchdog 并非绝对零策略，它会在截止时对所有有图的题代跑 `finish_flags`。所以正确的边界不是"守护层零策略"，而是：**确定性的收卷动作可以放在守护层，战术选择不能**。

**Pojun 现状**：`RestartTask`/`Resume` 在 `server/engine.go` 里，与调度语义耦合（上次僵尸任务就是这个病根）。

**动作**：抽 `server/supervisor.go`，只做三件事：进程/循环存活、到点收卷、异常重启。判据：supervisor 里不出现 intent/finding 相关逻辑。

## 三、核心设计：意图级四档阶梯

### 3.1 数据模型（最小改动）

`exploration_nodes` 加两列，避免从 activity 反推：

```sql
ALTER TABLE exploration_nodes
  ADD COLUMN first_run_at     timestamptz,        -- 首次进入 running 的时刻
  ADD COLUMN escalation_level smallint NOT NULL DEFAULT 0;  -- 0..4
```

`first_run_at` 在 `claimNext` 把 open→running 时写入；`escalation_level` 由阶梯判定推进，`ReopenIntent` 时清零。

### 3.2 阶梯表（唯一的判断来源）

| 级 | 触发条件 | 动作 | 成本 | 是否计入"决定性动作" |
|---|---|---|---|---|
| L0 | 首次领取 | 正常执行 | — | — |
| L1 | `elapsed > 0.4T` 且无新 fact | `steer_work` 一条具体战术指令（不是鼓励） | 0 | 否 |
| L2 | `elapsed > 0.7T` 且 L1 后仍无新 fact | 同资产起**第二条意图**，描述里强制写不同角度（黑盒 vs 源码/不同服务/不同漏洞类） | +1 worker | 是 |
| L3 | `elapsed > 1.0T` 且仍无新 fact | 该意图升档到 smart 模型重跑 | 1 次贵调用 | 是 |
| L4 | `elapsed > 1.3T` | `state=blocked` + `blocked_reason` 写明"试过什么、缺什么"，进停放清单 | 释放 worker | 是 |

**两条硬约束**（直接抄 sapper 的纪律）：
- **不得跳级**：L2 未做不能直接 L4；
- **升级计数器绑意图，不绑任务**：绑任务会让一个卡住的意图拖死整轮。

### 3.3 判定挂在哪里

不新开循环，挂在**现有 heartbeat 巡查**里（`server/engine.go` 心跳分支，已有 `steer_work`/`kill_work` 回调）：

```go
func (e *Engine) patrolIntent(t *Task, it *Intent) {
    if it.FirstRunAt == nil { return }
    el := time.Since(*it.FirstRunAt)
    T := e.budgetPerIntent(t)          // 剩余预算 / 未完成意图数
    if !hasNewFactSince(it, el*4/10) { // 近 40% 时间无产出
        switch {
        case it.EscalationLevel == 0 && el > T*4/10:
            e.steer(t, it)             // L1
        case it.EscalationLevel == 1 && el > T*7/10:
            e.spawnAngle(t, it)        // L2
        case it.EscalationLevel == 2 && el > T:
            e.escalateModel(t, it)     // L3
        case it.EscalationLevel == 3 && el > T*13/10:
            e.park(t, it, reason(it))  // L4
        }
    }
}
```

注意 `hasNewFactSince` 用**产出**而不是**活动量**判定：sapper 的经验是"静默不等于死机"（它靠消耗记录才敢不打断）；我们用 fact 产出更直接。

### 3.4 阈值公式的边界

- `T` 下限保护：`max(T, 5min)`，避免小预算任务一上来就 L4；
- 已完成意图不计入分母；
- 停放后若出现"能解锁它的新 fact"（比如缺的凭据拿到了），收官阶段由 planner 主动 `ReopenIntent`——这是 sapper 的 endgame reopen，但我们用**数据触发**而不是时间触发。

## 四、产品层可借鉴的四件事（用户可见）

技术机制之外，sapper 有几个产品形态值得直接借：

1. **战役看板**：一屏看到"在打什么 / 卡在哪 / 已确认什么 / 还剩多少预算"。Pojun 有图可视化，但缺"当前战役态势"这一层聚合。
2. **成本账本**：每次升级、每次贵模型调用记一条，可回溯"这 40 块钱花在哪条链上"。sapper 的 `generals` 计数就是这个思路的雏形。
3. **交接/复盘报告**：任务结束时自动生成"打了什么、怎么打的、什么没打下来、为什么"——这既是对账产物，也是交付物。
4. **暂停即快照**：暂停不是停进程，是冻结一个可解释的状态（现在跑到哪、下一步是什么），恢复后从快照继续。我们已经修过 resume 僵尸，这个能力是差异点。

## 五、落地分期与验收

### 第一期（P0，约 2.5 人日）
1. 加两列 + `first_run_at` 写点（`db/exploration.go` claimNext）
2. `patrolIntent` 挂进 heartbeat（`server/engine.go`）
3. L1/L4 先跑通（纠偏、停放），L2/L3 留桩

**验收**：造一个"故意无产出"的意图，观察它在 0.4T 被 steer、1.3T 被 blocked，且 `blocked_reason` 非空；正常推进的意图不被误动。

### 第二期（P1，约 2 人日）
4. reconcile pass（`server/auto_finish.go`）+ 对账簿
5. supervisor 抽取（`server/supervisor.go`）

**验收**：跑一个真实任务到收尾，对账簿能列出三类问题（无证据 finding / 有结论无 finding / 已确认未验证手法）。

### 第三期（P2，约 3 人日）
6. 模型两档 + 代码级配额断言
7. finding 的 `technique` 字段 + 指纹召回

**验收**：断网跑一个任务，把 smart 配额设为 2，第 3 次请求被拒并降级，日志有 `tier_denied`。

## 六、明确不抄

| 不抄 | 理由 |
|---|---|
| tmux 窗格 / 外部 CLI 驱动 | 复用内置独立 worker 会话和共享图，移植有界协作语义，不为角色名称再建进程框架 |
| 屏幕字符串判活 | 生产必炸；我们用进程与 DB 状态 |
| 绝对分钟阈值 | 换场景必失配，必须由预算动态算 |
| 同族迁移作为核心假设 | 它吃的是题库同构；真实目标没有 63 个换皮变体 |
| 把纪律只写在提示词里 | 它自己的默认模型就违反了 doctrine——纪律要落到代码断言 |
