# 10 · 分支与镜像约定

> 2026-11-05 定。起因：镜像是从 `main`（fbdd80e）构建的，线上二进制却是 `downstream/custom`（e8ae41e）热替换进去的——镜像描述与运行体差了一个提交，回滚会退到没有修复的版本。

## 一、分支

| 分支 | 定位 | 规则 |
|---|---|---|
| `main` | **上游合并基线** | 只放"合并上游 + 重放本地补丁"的结果。不接日常修复，保持可随时对比上游 |
| `downstream/custom` | **开发与修复线** | 所有本地修复、实验、分析文档都走这里；始终领先 main |

**不要把 main 快进到开发线**。main 的价值是"一个干净的上游对齐点"，一旦混入零散修复，下次合并就分不清哪些冲突来自上游、哪些来自自己。

## 二、镜像 tag

- **必须**用 `0.4.x-<短sha>`，sha 取自**构建时的 downstream HEAD**，例如 `0.4.54-e8ae41e`
- 日期 tag（`0.4.54-custom-20261105`）只能当人读别名，**不得作为回滚点**——同名重建会静默换掉它指向的镜像
- 同一个 sha 只构建一次；要改就出新 sha

判断当前线上下载的到底是哪份代码：

```bash
docker inspect <container> --format '{{.Config.Image}}'
docker exec <container> md5sum /app/pojun
```

## 三、回滚

**必须走镜像**，不许 `docker cp` 换二进制：

```bash
docker rm -f pojun-pojun-1
docker run -d --name pojun-pojun-1 ... pojun-local/pojun:<目标tag>
```

原因：前端是静态导出后 `go:embed` 进二进制的。只换二进制而不换镜像里的其余内容，会出现页面白屏或前后端版本错配，而且这种错配在日志里看不出来。

## 四、已知例外

`0.4.54-e8ae41e` 是 `docker commit` 出来的**运行体快照**，不是 Dockerfile 构建产物——它让镜像与线上一致，但**不可复现**。

下次正常发版必须回到 Dockerfile 构建，并在构建后核对镜像内 `/app/pojun` 与预期 sha 的二进制一致。

## 五、从 Dockerfile 重建（2026-11-06 首次打通）

此前一直用 `docker commit` 存运行体快照，属于第四节说的"已知例外"。首次真正
`docker build` 时撞到两个只在构建期才暴露的问题，记此备查。

### 1. 构建容器出不了网

现象：`apt-get install` 全部 `Err:` → `Could not connect to deb.debian.org`

DNS 能解析、TCP 连不上。**构建容器的网络与运行容器不是同一条路**：运行中的
pojun 容器直连 Debian 与 GitHub 都通，构建容器全断。

解法：把宿主机代理传给构建（Docker Desktop 用 `host.docker.internal`）：

```bash
docker build --build-arg TARGETARCH=amd64 \
  --build-arg HTTP_PROXY=http://host.docker.internal:7897 \
  --build-arg HTTPS_PROXY=http://host.docker.internal:7897 \
  --build-arg http_proxy=http://host.docker.internal:7897 \
  --build-arg https_proxy=http://host.docker.internal:7897 \
  -t pojun-local/pojun:<version>-<sha> -f Dockerfile .
```

### 2. shell 脚本的 CRLF

现象：`install-tools.sh: line 12: set: pipefail: invalid option name`

内容完全正确，只是换行符是 CRLF，`set -euo pipefail` 被读成带 `\r` 的选项名。
这类问题 `docker commit` 永远碰不到，只有真构建才会暴露。

已加 `.gitattributes` 锁 `*.sh` / `Dockerfile` / `*.go` 为 `eol=lf`。

### 3. 构建后必须验证，不看脚本看命令

```bash
docker run --rm --entrypoint sh <image> -c '
  for c in nmap ffuf nuclei sqlmap gobuster; do command -v $c || echo "缺失 $c"; done
  for c in smbexec wmiexec secretsdump atexec psexec; do
    /usr/local/bin/impacket-$c -h >/dev/null 2>&1 || echo "缺失 impacket-$c"; done
  du -sh /opt/SecLists'
```

首次构建出的镜像 7.66G（干净），此前 commit 快照 37.7G——差额是快照累积的
废弃层，不是工具变少了。
