## 3. 语义重叠：上游自建的同类机制 vs 本地补丁

按你点名的五类逐一判定（重叠 = 两套逻辑可能同时生效）：

**(a) 空转收尾（idle-stop）——无重叠。** 差集 22 个文件里没有 `agent/idlestop.go`，也没有任何"连续 N 轮无写回就收尾"的实现。我们 `agent/idlestop.go` 的产出率判据是独占的，不会有两套判据抢跑。

**(b) 意图优先级 / 调度——半重叠，最隐蔽。** 上游没实现调度器（无 open-slot 上限、无 aging），但 v0.4.50 把 `list_untested_assets` + `list_goals` 发给 **worker**，等于把"还有哪些没测、目标是否完成"的判断权下发到执行层。我们的 dispatch policy（`agent/tools.go` `SetDispatchPolicy` / `dispatchOpenLimit`）与 ladder（`server/escalation.go:15-30`，15/25/45 分钟三档）都假设"派不派"由 planner 单点决定。合并后是**双决策主体**：worker 可绕开 planner 自补未测资产，击穿 open-slot 背压与 frontier aging，队列水位、aging 时长会系统性漂移。

**(c) 收尾结算——语义重叠，不是代码重叠。** 上游没有 `reconcile`。但上游收紧了 finding 准入口径，`db/reconcile.go:40-60` 里 `NoEvidence`（无证据 finding 数）会显著下降甚至归零 —— 同一字段升级前后含义不同，历史基线不可比。

**(d) 模型分层——无重叠。** 差集内没有任何模型路由/换模型的代码；上游 `escalation` 注释里"不会自动选择或更换昂贵模型"是我们自己补丁写的（`server/escalation.go:26`），别误读成上游行为。

**(e) supervisor / 保活——无代码重叠，但有一处静默降级面。** v0.4.49 声称"continues 校验放宽"，代码不在差集内（见 §0）。真正相关的是合并期新增的 `seedWorkerReadOnlyToolsV054`：启动路径同步跑，失败只 `log.Printf` 不中断（`server/assembly.go:260-262`）→ 绑定迁移失败系统照常起，worker 就是没那三个工具。这条路径要和保活/自检对齐，否则体检页是绿的、能力是缺的。

### 最危险的三处

1. **证据闸门被合并期软化，"上游严格闸门"其实是可绕的。** 上游 `validateMechanicalEvidence` 要求 critical/high 必须有 HTTP 类机械信号；我们在 `7ad0184` 把它包成 `validateMechanicalEvidenceForRun`（`agent/finding_recorder.go:115-126`），只要 evidence 里 ≥2 行能在本次 run 的工具回显里逐字命中就放行。读代码会以为跑的是上游闸门，实际跑的是"我们的回验优先"。**要么删掉软化层，要么在 CHANGELOG 里承认这是本地策略**——现在这种"看起来是上游、实际不是"最难排查。
2. **worker 自主工具面 vs dispatch 背压。** `list_untested_assets` / `list_goals` 让 worker 自判补漏，与 open-slot 上限、frontier aging、escalation 三套本地规则并行；三者都基于"意图数量/等待时长"建模，worker 私自补测后模型输入失真，阶梯会误判"没进展"而去纠偏一条其实在推进的线。
3. **skill frontmatter 丢失。** 上游重写 `SKILL.md` 时删了 YAML 头，skill 直接加载不了（`fbdd80e` 已修）。这是"上游以文档形式交付能力、元数据在正文外"的典型坑：以后每次拉上游 skill 更新都要复查 frontmatter，漏一次就静默少一项能力，且不报错。

## 4. `db/schema.sql` 净变更

`git diff f716742 7ad0184^2 -- db/schema.sql` 输出 **0 行**。上游 v0.4.47 → v0.4.54 **没有任何 ALTER / CREATE**，零新增表、零新增列、零索引变更。

副作用有一处，但不在 `schema.sql` 里：

| 对象 | 变更 | 证据 |
|---|---|---|
| `settings`（键 `worker_read_only_tools_v054`） | 新增一次性的迁移标记 | `server/assembly.go:391-396` |
| `agent_tools`（worker 绑定） | 追加上 `expand_digest` / `list_untested_assets` / `list_goals` 三条绑定 | `server/assembly.go:399-408` |

两条结论：
1. **升级不需要跑 schema 迁移**，只要 `settings` 表可写、三个工具在 `tools` 表里已登记为 `System` + `Kind=builtin`（否则 `seedWorkerReadOnlyToolsV054` 直接返回错误、只打日志）。
2. 本地补丁加的 `exploration_nodes.first_run_at` / `escalation_level`（`db/schema.sql:196-202`）**上游没有同名冲突**，仍是我们的独占列，合并后不会被上游覆盖。

**是否必须重建镜像：是，且整层重建。**
- FROM 变了 → 基础层之后全部失效，不是增量；
- `RUN bash /tmp/install-tools.sh` 在 COPY 二进制**之后**执行 → 每次改代码都要重跑全部工具下载（arm64 走 QEMU 更慢），建议把工具层提到 COPY 之前；
- 构建机需能到 `api.github.com`、`github.com`、`codeload.github.com`、`danielmiessler/SecLists`；断网时 `COPY report/fonts/` 与 SecLists 无兜底，直接失败；
- gobuster 口径分裂：镜像走 GitHub 3.8+，二进制形态仍是 `KindApt`（`hosttools/hosttools.go:152`，bookworm 3.6）。
