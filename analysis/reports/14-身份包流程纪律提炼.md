# 14 - 身份包流程纪律提炼

> 对象：`AGENTS.md`（51 非空行）+ `rules/` 11 篇（1,183 非空行），共 66,468 字符。

## 0. 总判断

这套包不是安全方法论，是**执行器失效模式补丁集**。四个岔路口 —— 搜索 vs 挖掘、深挖 vs 扩面、写 vs 不写、问 vs 不问 —— 的失败同构：**便宜动作都能伪装成贵动作**（搜种子比进站便宜，堆条数比建清单便宜）。规则主体即切断这四条通道。

## 1. 范围控制

判据只有一条：**有没有给固定的面**。只给集团名 → 自由跳；给站、URL、文档、清单 → 锁面（`dig-scope` §0 表 12–19）。不用「目标多大」判 —— 大小会诱发自我说服，觉得「值得挖」就能改判。

锁面锁判据不锁字符串：§0.1 只禁「未进站 FOFA 全集团」「跳无关旁系域」「文档当种子扩集团」，必须挖入口 host、配置/JS 带出的业务 host、业务流跳到的子域/网关、同簇多 host（25–33）。

一种子闭环（83–121）锁的不是数量（种子无上限，135 行），而是**搜索与挖掘的原子性**：搜一个 → 洗 → 挖完 → 才搜下一个。囤池的害在绑定被切断：同种子活面可互相差分，混池后判不出归属与同皮，§3.3 同皮机制失效。

| 机制 | 防的失败模式 | 原文位置 |
|---|---|---|
| 一种子闭环，禁多种子一次搜完再挖 | 池化切断 host 与品牌簇绑定 → 同皮、股权闸、差分全失效 | §1.0.1 90–102 |
| 「池空立刻 done」与「条数到手 ≠ 搜完」并列 | 把可计数的检索量当不可计数的挖掘进度 | §1.0.1 110；§2 391 |

## 2. 反空转

空转是**可观测谓词**不是感受：`报告/` 长时间不增 + 只见 403/health/重复 path（364）。信号表 20 余行（362–390）每条锚定「违反哪一条」：独立标准会被另立标准绕开。

关键是白名单：抽 JS、还原签名、建对象图、打认证口算干活；磨验证码、默认口字典、同皮登录再试才算。**判据是动作类型不是耗时**（按耗时判，拖延即自证忙）；15～20 分钟只对瘦壳生效，肥面豁免（413）。

| 机制 | 防的失败模式 | 原文位置 |
|---|---|---|
| 闸 A：存未 §4.3 活 host，或近 15 分钟主扩面且清单未建、报告无增 | 用「再搜一批」替代「进站挖」 | §2.1.1 421–424 |
| 合法扩面靠白名单穷举，不靠理由充分 | 「理由充分」是最易被生成的许可 | 424 |
| 每条闸配「绝对不是这个意思」栏 | 过度泛化：把节奏约束读成能力上限 | §2.1.0 405–415 |

## 3. 报告唯一真源

唯一靠**修改权集中**，不靠内容正确：`format` 写死「只改本文件这两张表……禁止写到 Agents、src-value、dig-scope」（3–4）。

他文件只许指向不许复述：`hunt-iter` 要求判定时「打开磁盘 format『漏洞等级』那一格……不抄、不改、不再评一次等级」（18），且「读磁盘本文件，禁信会话冻住的旧副本」（23）。

裁决表（`AGENTS` 27–28）是**按问题域切片**而非权威排序：挖什么→`src-value`、报告→`format`、CORS→`cors`、白盒→`researcher`、范围→`dig-scope`、迭代→`hunt-iter`。切域不切文件，只在重叠区有先后；代价是版本只有行内日期戳，无 changelog。对照：Pojun 的报告面反着长 —— 两条路径各读一张表（一条读 findings、一条读图节点），定级 last-write-wins（`15` 篇 #9/#10）。

| 机制 | 防的失败模式 | 原文位置 |
|---|---|---|
| 报告规则只许在一文件两表内改 | 多处定义 → 改一处留两处 → 永远读到过期那份 | `format` 3–4 |
| 按域切片 + 两条单向边（范围压过「等继续」，迭代不压过范围） | 全序权威表误伤跨域；自主性被冻结 / 迭代打断范围 | `AGENTS` 27 |
| 匿名闸 / 认钥闸把表述问题转成事实问题 | 为凑标题重构叙事（带 Cookie 挖完、交稿摘 Cookie 标匿名） | `format` 16、36–37 |

## 4. 自主性

「禁止问」六处落点：`AGENTS` 48；`dig-scope` 7、53；§1.4 318–320 四条自检 + 逐字枚举黑名单句式；`anti-over-moralization` 45 归入「过度道德化」；`SKILL` 43 进红线。配套**合法真停白名单**（321）：用户叫停、锁面簇做完、环境全线不可用后的短报障。

本质是**取消停机选项、保留报障通道**：提问从「许可申请」降为「状态汇报」；边界画在可逆性上 —— 先加再删自己加的那条可以，改别人已存在的订单/密码/角色不行。

| 机制 | 防的失败模式 | 原文位置 |
|---|---|---|
| 「要不要继续」定性为违规收工，而非礼貌 | 礼貌性停机：交回决策权是成本最低、姿态最好的退出 | §1.4 280、318–320 |
| 黑名单句式逐字枚举（四种说法）+ 真停白名单穷举 | 换说法绕过原则；规则变「永不停」后遇真障碍只能硬撑或撒谎 | 320–321 |
| 缺条件时降级而非停机（缺对照号→测能测的） | 「信息不足」被扩大成全域停工 | §0.2 51–53；`researcher` 201 |
| 提问权按模式开关：自由跳禁用，白盒/写代码可用 | 一刀切禁问 → 工程场景失去必要澄清 | `researcher` §7 189–201 |
| 边界画在可逆性上：禁登出/revoke；改绑改密过了立刻改回 | 把「不许问」误读成「什么都能做」 | `SKILL` 28–34；§4.2.2 720 |

## 5. 反面清单

最极端是 `cors-vuln-report-priority.md`：229 字符、末行「CORS = 不挖」，却被引用五次以上（`AGENTS` 18/27、`format` 34、`src-value` 47/54、`dig-scope` 681），并升级为「**勿开** `cors-test.md`」—— 从不测到不加载。

否定式更硬有四个原因：**可验收**（当天可查矩阵里有无 CORS 行，「挖得深」无法验收）；**可剪枝**（不需理由，只在分支点剪掉）；**承载机会成本**（不挖 = 危害/工时比低于阈值，一次性决策固化成默认值）；**风险不对称**（肯定式漏了只是少做，否定式过界封死一个面）。

| 机制 | 防的失败模式 | 原文位置 |
|---|---|---|
| 第二层否定：「勿开模块」 | 只要模块在库里，模型迟早「顺便看看」 | `SKILL` 34、79、133 |
| 「不写」穷举到形态 +「拿不准也不写」；不写 ≠ 不测 | 边界模糊时默认放行；交付否定扩散成测试否定 | `format` 34 |
| 否定自带边界阀：禁报假点 ≠ 根域永封；单站没中 ≠ 手法死亡 | 一次否定被读成永久封禁 | `dig-scope` 276；`hunt-iter` 27–28 |

## 6. 硬约束统计与受众判断

12 文件 / 1,234 非空行：`禁止` 161、含「禁」177、`必须` 46、`不得` 13、`不许` 10、`不准` 7、`一律` 9、条件式「才」72；**15.2% 非空行含硬约束词**。分布极不均，这一点决定答案：

| 文件 | 硬约束行占比 | 该处自由度 |
|---|---|---|
| `hunt-iter` | 60.6% | 最高（自判什么值得进短表） |
| `format` | 41.9% | 高（措辞、定级、落不落） |
| `AGENTS` / `dig-scope` | 25.5 / 16.2% | 中 |
| `src-value` / `anti-moral` / `researcher` | 8.7 / 5.1 / 4.1% | 低（内容已给） |
| `playwright` / `cors` / `context` | **0%** | 零（纯路由与结论） |

**判断：目的是约束 LLM，内容是人写给自己的复盘，形式为 LLM 优化。** 依据两条：

1. 密度随「自由度 × 损害」分布，不随文件重要度分布 —— playwright 0%、`hunt-iter` 60.6%。若属文风，密度该跟篇幅走；预算被投在模型最易自作主张处。
2. 「禁止读成 / 不是这个意思」只对指令跟随者有意义，处理的是**过度泛化**：把「深挖优先」读成「禁扩种子」；24 条每轮心跳（781–805）与「压缩后先读三件套」（323）只对无状态、会被压缩的执行者成立。人类两条都不需要。

但确有给人看的一半：六个日期戳、「用户定死」署名。准确说法：**人写「我上次怎么错」，落成条文时改写成「禁止 + 可观测信号」**。代价是奖励字面合规 —— §2.1.0 与所有「禁止读成」正是补丁：**每条禁令都要配一条反误读**。

## 7. 两处结构性缺口

一、`researcher-blackbox-whitebox.md` 前 43 行是 `playwright-browser-mcp.md` 全文副本，第 44 行从半张表开始（Phase 0 缺失）。同一规则两处存在，违反 `AGENTS` 28 行「rules 无冲突」的前提：真打架时无仲裁。且这类副本多出在**许可条文**上（`AGENTS:7`／`skill-as-boost:6`）——无可校验参数，漂移不被任何闸发现。

二、66k 字符与上下文硬冲突，解法是加索引层（`hunt-iter` 25、`SKILL` 106）：全量加载换成「索引 + 按需指针」，代价是须与正文同步。

迁移时该带走的是三个形式：**判据表配反向禁令**、**每条闸配「不是这个意思」**、**每条否定配边界阀**——共同前提：**禁令单向**（只禁一个方向），**许可反向**（只去上限、不设新限），两类不可互推。
