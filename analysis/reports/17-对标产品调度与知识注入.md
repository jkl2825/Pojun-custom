# 17 对标产品：调度结构与知识注入

> 对象：`pentest-platform`（只读）。范围 `harness/pa_kernel/`、`server/`、`docs/`，跳过 `client/bbot/`。
> 一句话结论：这套系统的关键不是"三层"，而是**每层的会话寿命**和**谁有权限写共享状态**。observer 也不是"审查员"，它是**带写权限的近场记忆维护者**。

---

## 1. 三层职责：上下文靠"数据源不同"隔断，不靠提示词

| 层 | 会话形态 | 看得见 | 看不见 | 证据 |
|---|---|---|---|---|
| PM 总控 | `mainagent:<pid>` 项目级长会话 | 用户对话史、任务、审批、战役清单 | 任何 run 内部的工具调用 | `docs/claude/engine.md:5`, `docs/articles/01-overall-design.md:52` |
| planner | `planner:<pid>:<cid>`，每战役一条，**每轮全新上下文** | 平台从图与战役模型渲染的【你的战役】+【本轮触发】+【战役态势】+【约束】 | 上一轮自己想过什么、任何聊天史、用户注入面 | `server/apps/engine/planner/session.py:1-19` |
| PA（run） | 每使命一个 run | 任务书（冻结）、工具结果、hunt brief、图增量 | 兄弟使命的过程、planner 的判断、其他战役 | `docs/articles/01:54` |

隔断是结构性的，不是纪律性的：

- planner 的轮输入是**单条 user 消息**，全部由 `render_campaign_focus` 确定性渲染（`planner/session.py:211+`），系统提示词钉死"图上没有的你不臆测"（`planner/prompts.py:62-64`）。它**没有可继承的历史对象**，所以"别背着三个月对话做判断"不需要靠自觉。
- PA 的任务书是 100k 字符封顶、派发时一次性拼装后**冻结**（`docs/articles/02:102-104`）。历史上曾每轮重渲染，一个 run 在 27 分钟内把整本书注入了 7 次，之后裁决冻结。
- 子代理隔离更硬：`initial_messages=[user(prompt)]`，零继承父对话（`docs/claude/harness.md:86`）。
- 反向的一处刻意例外：PM 每轮装配**不做体积裁剪**（`engine.md:67`），因为截断序曾把"近期聊天"和"审批答复"整段丢掉——那是不可恢复的损失，而缓存未命中可以重读。

## 2. 使命粒度：35 分钟，且结束条件有三道锁

- 1 mission : 1 run（`engine.md:5`）。时长生产配置 2100s、代码缺省 2700s（`docs/articles/01:134`；`server/apps/runs/services.py:81` `MISSION_RUN_MAX_DURATION_S = 2700`；`server/apps/system/models.py:128` 缺省同为 2700）。
- **只限时长、不限轮数**（`services.py:566-581`；`server/apps/engine/dispatch.py:1036-1048`）。预算刻意**不写进任务书**——写进去就变成"什么时候可以结束"的暗示。
- 结束三重叠：
  1. 预算 watchdog 强杀（兜底，非语义）；
  2. `try_finish`：无未收束 step、无未读贡献 → 有 supported 漏洞则 `goals_met`，否则 `paths_exhausted`（`harness/pa_kernel/pentest/journal.py:934-954`）；
  3. 终局门必须先过 observer 的 `allow_finish`，`continue` 有**否决权**（`harness/pa_kernel/loop/runner.py:1252-1256`；修此门序前 145 个 run 里 138 个 `observer_verdict=null`）。

**与"一个意图 9 分钟"的粒度差**：不在 35 vs 9。对标文里明确反思过更短的形态——参考系统 worker 一意图一会话、默认 1200s、3 并发，4 小时约 36 次重决策；他们没有照抄，而是选了 35 分钟 + 中途审查 + 接续使命血缘（`docs/articles/01:118-130`）。真正的差别是：**9 分钟到点后，没打穿的那条链有没有一条"接续使命"接上**。他们用 `continues_from` / `parent_mission` 把"续接"变成 schema 约束，续接使命的任务书从上游战报摘要取材（`engine.md:6-14`）。粒度小本身不产生接力，血缘才产生接力。

## 3. observer：异步、局部、有写权限

- **双触发**：periodic（轮数轴，缺省 30 轮，`harness/pa_kernel/platform/executor.py:1571`）与 completion（终局门首探 ignite，`executor.py:936-956`：`gate.register` 占住终局门，完成回调 `complete(notify=False)` 即时放行）。periodic 是**背景任务**：探针只 drain 上一轮结果 + 判 due，审查本体 `asyncio.create_task` 后立即返回，单飞、在飞跳过不排队（`executor.py:1056-1133`）。
- **观察什么**：一份快照 = 主对话 `ctx.messages` 全量 + 用户/系统上下文 + plan + hunt brief + 子代理任务 + **16K 能力目录**（`pentest/observer.py:678-691`），在 ignite 时定格（`executor.py:958-991`）。它是 SECONDARY 档的一次性会话，≤5 轮、第 5 轮强制 final、300s 软截止（`observer.py:162-166`）。
- **注入什么（关键）**：两条通道，第二条才是重点。
  1. 文本通道：`continue` → `<observer-guidance>` 以 user 消息注入主对话，consume-once（`observer.py:442-486`；`runner.py:1293-1310`）；`allow_finish/failed_open` → 只落展示位。
  2. **写记忆通道**：observer 的可写面含 `HuntState`，以 `observer:` 前缀做 actor 信任解析（`prompts/observer.py:34-43`；`pentest/hunt_state.py:126-164`），写完自动标 main 未读（`harness.md:104`），下一轮 `build_hunt_brief` 就把它念回主代理（`journal.py:598-618`）。
- 所以"主动知识注入"不是塞一段建议，是**把建议变成持久记忆，再让它自己回流**。它甚至能替主代理补 Step（"分支在验证但台账里没有对应 Step → 审查结束前 `step_create`"）。
- 纪律：**fail-open**，审查不可用就放行（`observer.py:167`），监督面永不拖垮交付面。

## 4. 知识召回：蒸馏 + 平台管道式主动召回

**（a）终局蒸馏**：run 终局才入队，零产出跳过；输入只有会话轨迹（不塞 hunt）；一次 LLM，上限 8 条，8 条硬规则（脱敏/禁原文/迁移判据/否证需实测死因…）+ 人工审批（`pentest/distill.py:91,159-224`；`docs/articles/01:330-340`）。

**（b）主动召回 Scout**——这是"平台管道，不是 agent 自觉"（`01:342-346`），实现在 `server/apps/agent_host/knowledge_scout.py`：

| 环节 | 做法 | 证据 |
|---|---|---|
| 节拍 | 15s 轮询，满 10 轮触发一拍 | `:39`, `:342` |
| 输入 | 会话尾部 10 轮 + hunt 快照 + 查询历史，预算 ≤100k | `:83-95` |
| 决策 | 单发强制工具三选一 `search/load_skill/skip`，查询至多 3 词（三词法） | `pentest/scout_tools.py:70-118`；`prompts/knowledge_scout.py:47-65` |
| 召回依据 | **向量+全文融合检索**，跨 `experience/skills/vuln` 三集合 | `:46-50`, `:757-783` |
| 终审 | 逐查询 top-1 送 LLM judge 只答 yes/no | `:63-75`, `:651-697` |
| 注入 | `round_probe` 链，`<system-reminder>` + `is_meta` | `server/apps/agent_host/kernel_loop.py:1361-1396` |

召回**不是 embedding 也不是图**：文档直接说"用图做知识检索实测效果差，检索要的是相似度，不是拓扑，这条路已放弃"（`docs/articles/02:30`）。图负责"东西在哪"，KB 负责"以前见过类似的问题吗"（`02:198`）。

## 5. 图协同：写节点即通信，2s 投影 + 边沿唤醒

- 节点六类（run/outcome/intel/finding/path/evidence），边只有三种语义：`parent`（run 树）、`GraphAnchor`（→资产）、归属列（`campaign_id`/`origin_run_id`）（`docs/articles/02:7-26`；`server/apps/engine/hunt_sync.py:109-115`）。
- **没有 agent 间消息通道**：PM 不给 planner 发消息，PA 之间不互发（`02:34-35`）。信息流 = 写图 + 唤醒。
- 链路：hunt mutation → L1 `HuntGraphNode` → 2s tick → L2 `GraphNode`（只投 intel/outcome/`[finding-candidate]`，path/evidence 单列 cap，`hunt_sync.py:45-138`）。tick 是 `HUNT_PROJECTION_TICK_S = 2.0` 的节流档 + 轮转游标防饿死 + 全链幂等（`server/apps/runs/management/commands/run_scheduler.py:213-232`；`engine/hunt_projection.py:20-30`）。
- **实时性靠"每轮拉"而非"订阅推"**：agent 侧每轮装配时取本战役增量，按 `(node_id, updated_at)` 去重、排除自产节点、超预算渐进截断（`context/attachments/project_memory.py:188-250`），own 段 1200 token / 跨战役 brief 段 360 token（`:74-95`）。
- 唤醒是**边沿**：只有 outcome 或漏洞候选（`notable`）才 `fire mission_result`，`dedup_key=projection:<campaign>` 按战役去重（`hunt_projection.py:41-44,79-92`）。纯情报不打断调度。

## 6. 可否定量

**有结构上界，没有生产测量数据。**

| 项 | 结构成本 |
|---|---|
| observer 单次 | 输入 ≈ 主对话全量 + 16K 目录 + 24k 字符 hunt brief；≤5 轮；SECONDARY 档；max_tokens 4096 / 强制轮 8192（`observer.py:1322-1377`） |
| periodic | 每 30 轮一次，后台跑，不阻塞主循环 |
| scout | 每 10 轮 1 次决策（≤16384）+ ≤3 次 judge（各 512） |
| 图增量 | 固定 1200 + 360 token/轮 |
| 蒸馏 | 终局 1 次，≤8 条 |

只有反例数据（能说明代价，不能说明开销）：145 run 中 138 个 verdict 缺失（`runner.py:1252`）；100 run 误杀 61 个兄弟工具调用（`harness.md:50`）；27 分钟重注入 7 次（`02:114`）。"28% 采纳率"是运营口径、不在代码里（`harness.md:115`）。
**未找到**：token/延迟实测汇总、observer 命中率、scout 注入后的效果对比。

## 7. 我们结构上最该补的一条

**只改执行层：在 run 的终局门装一个"对抗性完成复核 + 强制写回"，不动 planner。**

理由：我们的意图只有 9 分钟，**上下文新鲜度已经优于对标**（他们花 35 分钟才换来一次重决策），照抄它的粒度是错的方向。我们真正缺的是那个门——把"意图自称做完了"换成"证据对账通过、观察已落共享层"。没有这道门，9 分钟一到，worker 的"这条没打穿、因为 X"只留在它自己的会话里；下一个意图从零重撞同一扇门，这就是"多层靶场打不穿"的真实形状。

落地要点（可完全照搬其形状）：

1. 触发点选**终局门**（不是轮边界）：首次探测即 ignite 并占住 gate，审完才放行；9 分钟的 run 跑不到 30 轮，periodic 不会触发，completion 才是唯一有效位。
2. 输入 = 会话尾部 + 本战役图增量 + 漏洞/观察台账；输出二值 `allow_finish / continue`，**必须走强制工具出线**（结构化，不接受自由文本）。
3. 给它**写权限，但只给写共享记忆的工具**（落图/写台账），不给探测工具——它的职责是"补写回"，不是"替打"。
4. 复核标准直接抄三条：区分"发送过请求"与"完成有效测试"；报告主张逐条对漏洞册；报告点名的结果必须有对应写回（`prompts/observer.py:75-101`）。
5. 纪律：fail-open、≤5 轮、300s、SECONDARY 档、`continue` 有否决权且 consume-once。

不做的事：不缩短/不延长意图时长，不加层，不改 planner 的派单逻辑。
